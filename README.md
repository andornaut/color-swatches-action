# color-swatches-action

[![Release](https://github.com/andornaut/color-swatches-action/actions/workflows/release.yml/badge.svg)](https://github.com/andornaut/color-swatches-action/actions/workflows/release.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/license/MIT)

A GitHub Action and CLI tool that extracts hex color codes from files and generates color swatch images (SVG or PNG).

Supports all CSS/VS Code hex formats: `#RGB`, `#RGBA`, `#RRGGBB`, and `#RRGGBBAA`.

## Usage

Add to your workflow:

```yaml
- uses: andornaut/color-swatches-action@v1
  with:
    files: "README.md"
    out-dir: "swatches"
```

### Inputs

| Input     | Description                                                   | Default    |
| --------- | ------------------------------------------------------------- | ---------- |
| `files`   | Space-separated files to extract colors from (supports globs) | _required_ |
| `format`  | Output format: `svg` or `png`                                 | `svg`      |
| `out-dir` | Output directory for swatch files                             | _required_ |
| `commit`  | Commit the generated swatches and push them to the branch     | `false`    |

### Example workflow

```yaml
name: Generate color swatches

on:
  push:
    branches: [main]
    paths:
      - README.md

  workflow_dispatch:

permissions:
  contents: write

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7.0.1

      - uses: andornaut/color-swatches-action@v1
        with:
          files: "README.md"
          out-dir: "swatches"
          commit: true
```

## CLI / npm usage

The script can be installed as an npm package directly from GitHub:

```bash
npm install github:andornaut/color-swatches-action
```

Then run it via npx or an npm script:

```bash
npx color-swatches [--format svg|png] <out-dir> <file...>
```

Example npm script in `package.json`:

```json
{
  "scripts": {
    "swatches": "color-swatches --format png swatches themes/*.json"
  }
}
```

## Quick setup

Run the setup script to generate the workflow file in your repo:

```bash
bash <(curl -s https://raw.githubusercontent.com/andornaut/color-swatches-action/main/setup.sh) \
  --files 'README.md' \
  --out-dir 'swatches'
```

## Referencing swatches in markdown

The generated files are named by hex value (e.g. `ff0000.svg` or `ff0000.png`). Reference them in your README:

```markdown
| Color                           | Hex       | Usage   |
| ------------------------------- | --------- | ------- |
| ![red](swatches/ff0000.svg) Red | `#ff0000` | Primary |
```

## Container checks

Docker and Make run verification without a host Node.js installation:

```bash
make check
make check-info
```

`make check` runs every declared lint, test and build check in an isolated
container. `npm run check` is the native alias. `make lint`, `make test` and
`make build` run individual categories; an undeclared category fails explicitly.
The checkout is read-only during checks, and caches and generated files stay in
container scratch storage. `make exec COMMAND='npm update'` runs an intentional
package operation with writable project files and protected Git metadata.

No test suite is declared.

`make staged` retains host lint-staged for stash and staging operations. Prettier and
ESLint fixes run inside containers. Hooks require host Node.js and the project's
local lint-staged dependency; prepare dependencies with
`make exec COMMAND='npm ci'` without a host package installation. Git rollback and stash cleanup stop when a
container writer remains unresolved, preserving the working files and backup.
